新交付规则（从下一步 Journal 映射开始）：

1. 一个完整功能/页面映射步骤中的**所有必要修改文件**，必须**在同一轮答复里一次性交付**，不能“一个文件一轮”地拆散教程。
2. **不改变用户手动修改代码的方式**：每个文件/每个有界区块均保留明确目录、旧代码精确搜索、唯一/预期命中数量、精确新代码、大小和行数预期、语法校验、回滚代码/说明。
3. 在交付教程之前，先审计该步骤的**完整文件依赖**并列出文件清单、修改顺序和影响面。禁止遗漏同一步必须联动的 PHP/CSS/JS/模板。
4. 同一步可以包含文件级安全检查点，但**交付文件修改教程必须完整呈现于同一轮**；完成全部修改以后进行本步骤统一功能、桌面、移动、主站隔离回归验收。
5. 不交付用于覆盖的整个主题 ZIP；不要求一次性整文件覆盖；不以追加 CSS 补丁替代精确变更。
6. 若一项代码变更存在真实硬性先决条件尚未确认，则标为阻断并说明，不发布不可靠的部分实施代码；确保「一个步骤完整教程」的前提是真实基线和设计已足够确定。

这项用户最新要求变更**交付批次和沟通节奏**，不放宽《Strict 1:1》《Manual Replacement》《Verified Full-File Replacement》的安全门槛。
