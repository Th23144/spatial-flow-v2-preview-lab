## Exact source findings

### 1. White Cart canvas

The Canonical Cart block defines `--sf-cart-bg: #f6f1eb`, but does not explicitly assign it to Astra's Cart page wrappers. Astra/page wrappers remain capable of painting a white surface above the global body background.

Correction: assign the warm Cart canvas only to Cart-scoped page wrappers inside the existing Canonical Cart block.

### 2. Missing breadcrumb

No Cart breadcrumb renderer exists in the current `functions.php`. The Cart heading is rendered at `woocommerce_before_cart` priority 6.

Correction: add a backend-editable breadcrumb renderer at priority 5, immediately before the existing heading, using real site home URL and Customizer-owned labels.

### 3. Recommendation image readiness

Current recommendation eligibility checks publication, visibility, purchasability and stock, but does not require a real featured image and does not provide a product-level exclusion control.

The renderer intentionally falls back to the package/cube icon when `get_image_id()` is empty. This explains the cube placeholder in the screenshot.

Correction:

```text
- require a valid featured-image attachment URL before a product can enter Cart recommendations
- add backend product checkbox: Exclude from Cart recommendations
- enlarge dynamic candidate pools so four image-ready products can still be found
- remove the generated fallback marketing sentence when a product has no authored description
```

The white label/arrow fragment in the Natural Silver Obsidian image is not generated by Cart CSS or markup. The recommendation image slot is a plain background image with no pseudo-element overlay. That artifact belongs to the product's current featured image/crop. Replace/crop the image or use the new exclusion checkbox.
