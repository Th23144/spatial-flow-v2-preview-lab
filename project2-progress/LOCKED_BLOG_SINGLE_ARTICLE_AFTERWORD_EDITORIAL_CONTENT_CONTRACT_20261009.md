# LOCKED · Blog Single Article — Afterword / 后记的内容契约
日期：2026-10-09
项目：项目二 · Spatial Flow Blog / Journal 子站换皮
状态：**用户已明确认可本文件规定的内容定位，作为后续文章编辑、页面调整和 WordPress 映射的强制参照。** 不代表生产 WordPress 代码已经完成。

> **一句话原则（用户特别认可，必须在后续窗口完整继承）：**
> **Afterword 应该是「文章内容的一部分」，而不是「设计的一部分」。**
> 视觉模块为内容服务，不允许为了填满一块好看的区域而生造后记。

## 1. 什么是 Afterword？
- 统一中立名称：**Afterword（后记）**，而不是全站强制固定为 Editor's Note（编者寄语）。
- 它是**一篇具体文章结束后的可选内容段落**，用于留下作者/编辑的补充观察、创作背景、开放问题、必要的延伸思考或编辑说明。
- 正文应该先完整回答主题；后记不能替代正文结论、技术步骤、事实依据、关键安全提示和护理限制。
- 它不是产品营销位、广告、会员付费入口、相关文章卡片、读者评论区，也不是所有文章都要有的默认抒情标语。
- 不要求文章以哲理总结结尾，也不要求每篇后记都带有问题句；具体是否设置标题、何种语气，由**文章真实内容**决定。

## 2. 作者还是编辑部？
**不要在文章设计阶段硬性二选一。** 根据实际责任主体署名：
- 作者撰写的补充：可以显示 `Author's Note / 作者后记` 与真实作者名。
- 编辑撰写的补充：可以显示 `Editor's Note / 编者后记` 与真实编辑或编辑部名称。
- 共同编写或不需要特别区分的内容：使用中性的 `Afterword / 后记`，署名可选，但不可错署名。
- UI 顶部默认采用中性的 `Afterword`；底部原设计的两侧文本属于**署名/文体元数据**，不是两个功能按钮。不能全站写死 “Spatial Flow Journal / Editor's Note” 造成事实性错误。
- 后记可以保持现有中文题签「讀畢 · 餘白」的视觉语汇，但不要求每篇文章用同一套实际正文。

## 3. 显示与编辑规则（未来生产映射的内容行为约束）
- **每篇文章独立编辑**，归属到真正的 WordPress Post；不存在为了设计演示而全站共用的固定后记正文。
- 可选字段能力：后记标题、后记正文、类型/来源、可选的真实署名。实际 UI / WP meta keys 之后依最新安装源码审计决定，**此处不锁技术实现键名**。
- **未提供有意义的后记正文 → 整个 Afterword 区块隐藏**，不输出空白容器、空标题或套话占位。
- 允许不设标题或署名时的雅致缺省视觉，但不能据此自动生成一段哲理文案。
- **不允许通过 AI / 模板在没有真实内容时自动生成通用后记**；可以在得到明确的编辑授权后协助撰写，经作者/编辑审核才作为正文发布。
- 普通知识文、护理教程、技术说明或简短公告未必适合后记；长文、空间观察、文化随笔、深度阅读等通常更有可能适用。以实际内容价值为准，不以文章类别硬性强制。
- 后记文本必须由后台可编辑、可撤销、可更新，并与该文章一起正确保存与渲染，不得作为前端写死的 HTML 文案。
- 若编辑将来不再需要后记，清空字段后前端应自然消失，不留下空位。

视觉层保持原版大幅横向居中、细线与短朱砂强调、中英文题签、下部左右署名区。屏幕截图中的**红框是用户标注，不是边框设计要求**。

稳定顺序：
`正文与脚注 → Afterword（有内容时）→ 作者信息 → 上一篇/下一篇 → 三篇相关阅读 → 原版开放文库阅读引导（Reading Invitation）→ Journal Dispatch → Footer`。

**特别重要：Afterword 与 Reading Invitation 是两种不同内容。**
- Afterword = 结束这篇具体文章的思想/写作表达，**不应充当第三个“继续阅读”CTA**。
- Reading Invitation = 引导探索公开文章与分类文库，原版 `Some questions deserve a longer shelf` 的视觉布局继续保留；不因为采用 Afterword 而删掉。
- 这两个板块曾因错误的“去重”被误删过一次，并在 Article04 恢复；**今后不得在未明确讨论前互相替换或合并**。

## 5. 内容验收：以后用户说“改文章”时必须重新读取这里
每次修改 Single Article 模板，或讨论博客某篇文章编辑时，检查：
1. 当前文章**真的需要**后记吗？其独特信息是什么？若没有，隐藏。
2. 标题/正文是否属于**这篇**文章？是否有明确的内容价值，而非模板性抒情？
3. 正文是否已完整交代事实、结论及重要事项？后记是否只是自然延伸？
4. 署名是否反映真实写作者？作者/编辑身份未确认时不得臆造。
5. WordPress Post 中是否可单独编辑、保存、清空？不影响正文、目录、SEO 和其它文章。
6. 检查其后仍保留独立的 Author、Previous/Next、Related Posts 和 Reading Invitation；禁止用后记替代这些模块。
7. 桌面/手机阅读节奏是否仍然适合？文本过短或过长可调整视觉排版，但**不应为了填满设计而扩写内容**。

## 5A. 新增锁定：映射时必须主动提醒，并以编辑教学替代误导性占位（用户 2026-10-09 明确要求）

> 用户要求：“以后映射这个板块的时候，一定要提醒我，或者说映射的时候，这里的文案本身就呈现教学的文案而不是现在这种的占位。”

**这是正式生产映射的必查闸门（MAPPING REMINDER GATE），不能因换窗口或换人而遗漏：**

1. **在开始 Single Article 的 Afterword 映射之前，必须主动向用户指出此规则并核对**：Afterword 是每篇文章可选的、有内容价值的后记；它不是固定样板感悟，不是广告/继续阅读入口。不可默默带着当前演示文本进生产。
2. **后台编辑器中必须能看见用途说明或编辑引导**。优先为 WP 编辑控件提供说明文字、帮助提示或明确示例，例如：
   - 后记标题（可选）：填写与**当前文章**相对应的标题，不需要套用固定哲理句；
   - 后记正文（可选）：仅当作者/编辑确有补充观察、写作背景或延伸问题时填写；**无内容请留空，前端会隐藏整个后记**；
   - 署名/类型（可选）：填写真实作者、编辑或编辑部，避免固定署名。
3. **静态预览/编辑态如需保留示范，则必须明确标注为“编辑教学示例 / 不随文章发布”**，示范文案应解释怎么使用，而不是现在那种可被误认作正式内容的固定抒情占位。
4. **面向读者的正式前端绝不能显示“请填写后记”“这是模板示例”之类教学文案**：有经编辑保存的真实后记才显示其真实内容；没有内容则整个模块不渲染。这与第 3 节“无内容即隐藏”的规则同时生效。
5. 页面视觉布局保留 Article04 的后记形态，教学帮助属于编辑后台或设计演示层；编辑教学**不算正式后记数据**，不得自动保存为 Post Meta、默认正文或 SEO 内容。
6. 必须在 WordPress 映射验收清单新增实际操作测试：打开一篇没有后记的文章（前端无板块）；填写后记并发布（前端正确呈现）；编辑与清空（同步更新/隐藏）；核对后台说明文字确实可见，且无原型示例内容泄漏。

### 映射执行前必须朗读/复核的提醒

**“现在开始映射 Afterword：请记住它是内容模块，不是固定装饰。后台提供用途教学，前端只显示真实文章后记；没有填写时隐藏。不能把设计稿中 ‘Leave the room with one small question’ 或 ‘A Note from the Editors’ 作为所有文章的默认文案。”**
