# Wishlist reference strategy correction — ecommerce wishlist refs are functional, not visual authorities

Date: 2026-09-20
Repository: `Th23144/spatial-flow-v2-preview-lab`

## User feedback

The user challenged the visual judgment behind the recent Wishlist iterations and asked whether the design process had any real aesthetic discernment.

## Evidence-based correction

A second review of real luxury Wishlist/Favourites examples shows the prior V8 conclusion was too shallow.

Observed patterns:
- Mytheresa: large product-image grid with move-to-cart actions; visually polished but still clearly a product wall.
- NET-A-PORTER: sparse grid/list with availability state; useful functionally, but still catalog-like.
- THE OUTNET: sorting/filter controls plus product cards; strongly commerce/catalog oriented.
- COS: empty state is appropriately restrained, but this only informs empty-state behavior.

These references are useful for:
- stock state;
- move-to-bag behavior;
- remove behavior;
- empty-state restraint;
- saved-item semantics.

They are NOT sufficient as the visual composition authority for Spatial Flow.

## New authority split

### Functional Wishlist references
Use SSENSE / Mytheresa / NET-A-PORTER / COS / similar only to validate expected saved-item behavior and commerce truth.

### Visual composition references
Use the project's stronger design corpus instead:
- A24 Shop;
- Squarespace Foundations;
- Everyday^;
- Dropbox Brand;
- House of Spoils;
- Palmer Dinnerware;
- accepted high-quality Project 2 editorial-commerce work.

The Wishlist composition should borrow:
- pacing;
- whitespace;
- typography;
- editorial hierarchy;
- asymmetry;
- authored spatial control;

while keeping Wishlist functions native and obvious.

## Critical rule

Do not copy the visible layout of generic or luxury Wishlist pages just because they are Wishlists.

Function reference != visual authority.
