# External-AI batch design scope — Account through Utility/Policy

Date: 2026-09-22
Repository: `Th23144/spatial-flow-v2-preview-lab`

## User decision

The user wants to pause blind in-house visual generation and let another AI attempt the remaining non-blog main-site pages as one design batch.

The positive visual reference for this batch is the externally generated:
`Spatial-Flow-Wishlist-Edition-03.html`

## Batch scope

Create design prototypes for:
1. Account / My Account — optional future concept only.
2. Search.
3. 404.
4. About Us.
5. Contact Us.
6. Utility / Policy family.

## Account constraint

The user currently does not plan around a login/account system and may never enable one for the commerce site.

Therefore:
- do not assume authentication is available;
- do not build or imply a production login/registration system;
- Account is only an optional future frontend concept;
- it must not become a required site-navigation dependency.

## Utility / Policy scope

Use a reusable family/template approach for text-heavy policy pages such as:
- Privacy Policy
- Terms & Conditions
- Shipping Policy
- Cookie Policy / accessibility or similar future utility pages if needed

Do not reopen already completed/support pages merely for completeness.

## Explicit exclusions

Do NOT include in this design batch:
- Wishlist itself (already has the external candidate);
- Track Order;
- Services;
- FAQ / Help;
- completed Returns / Refunds work;
- Blog Header / Footer;
- Blog Home;
- Blog Issue;
- Blog Article;
- Project 3 pages.

## Visual handoff rule

The external AI should inspect `Spatial-Flow-Wishlist-Edition-03.html` and use it as the primary visual-language reference for this batch.

Do not mechanically clone the Wishlist layout across every page. Preserve the same brand system while giving each page an appropriate composition.
