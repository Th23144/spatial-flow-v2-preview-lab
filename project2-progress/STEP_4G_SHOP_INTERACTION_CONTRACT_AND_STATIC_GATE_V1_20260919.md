# Step 4G — Shop interaction contract + static admission gate V1

Date: 2026-09-19

## A. Interaction contract

### A1. Entering Shop
Before:
- shared Header V2.

After:
- one quiet landing field.

The first interaction should communicate:
`this is a place to explore objects, not a sales splash page`.

### A2. Discovery state
Candidate states:
`OBJECT / SPACE / MATERIAL / CUSTOM`

Default state:
`OBJECT`

Rules:
- compact labels;
- only one active state;
- state changes reorganize one shared field;
- no four-panel dashboard;
- no mega carousel;
- no permanent explanatory copy.

### A3. State continuity
When switching state:
- retain at least one spatial anchor;
- avoid full fade-to-blank replacement;
- change grouping/position/crop with visible continuity;
- motion ends fully; no ambient residual movement.

### A4. CUSTOM state
CUSTOM is special but not louder.

It should:
- shift the field from choosing to making;
- expose one concise Studio proposition;
- show material/bracelet signal;
- offer one entry into Studio.

It should not:
- expose the Studio toolset;
- become a mini configurator;
- duplicate Studio Home.

### A5. Archive transition
When user scrolls/leaves discovery:
- visual density increases;
- operational UI becomes more explicit;
- Filter / Sort / Count arrive;
- product grid becomes dominant.

This is intentional:
`atmosphere -> discovery -> commerce utility`.

### A6. Archive interactions
Use existing accepted runtime behavior.

Do not replace proven WooCommerce interactions simply to make them more artistic.

## B. Static visual admission gate

Before any HTML candidate is shown to the user, all must pass:

1. One decisive focal point visible in first screen.
2. No dependence on beautiful gemstone imagery.
3. Motion disabled: still feels authored.
4. No generic luxury hero.
5. No card wall.
6. No excessive rounded containers.
7. No more than two visible actions above fold.
8. Shop identity is clear without shouting "SHOP".
9. First product/archive utility reachable within a reasonable scroll.
10. Discovery layer feels like a system, not a row of category cards.
11. Studio presence is memorable but not promotional.
12. Existing archive can attach without visual rupture.
13. Mobile composition is independently designed.
14. Replace all product images with gray placeholders: hierarchy still works.
15. Remove logo: visual logic still works.

If 3 or more of these fail:
INTERNAL KILL.

Do not show the user.

## C. Candidate composition brief — Mother Direction 01

Working name:
`OBJECT FIELD -> ARCHIVE`

### Stage 1 — Opening Field
- asymmetrical but stable;
- one primary object image or object/room relationship;
- small Shop/season/current-edit metadata;
- restrained title;
- one route: Explore current objects.

### Stage 2 — Discovery Seam
- compact axis selector;
- one wide shared field;
- OBJECT default;
- switching SPACE / MATERIAL / CUSTOM changes field hierarchy;
- no separate cards.

### Stage 3 — Archive Threshold
- strong rule;
- `THE QUIET ARCHIVE`;
- product count;
- filter/sort.

### Stage 4 — Existing Archive
- protected grid;
- pagination;
- accepted Closing Note.

This direction should be tested first because it best satisfies:
- object priority;
- commercial clarity;
- low-noise discovery;
- existing Shop reuse;
- Studio integration without duplication.
