01 · Overview

Use the original content.

This template is not meant to rewrite your existing policy pages. The live implementation should preserve the original text, headings, legal wording, dates, links and SEO content while applying a cleaner Spatial Flow V2 visual layer.

It is suitable for Privacy Policy, Terms & Conditions, Refund / Returns Policy, Shipping / Help, Cookie Policy, accessibility notes, and other utility pages where readability matters more than custom layout.

The content stays yours. The template only gives it margins, hierarchy, rhythm and a calmer reading surface.
02 · Scope

What the template should style.

The live version should support common WordPress content blocks without requiring page-by-page rewriting:

  • H1, H2, H3 and paragraph hierarchy
  • Numbered and bulleted lists
  • Tables for shipping, returns or policy comparisons
  • Inline links, contact details and update notices
  • Callout boxes for important notes

What it should not change

It should not alter URLs, redirects, legal wording, privacy settings, WooCommerce policy assignments, SEO metadata, menu structure or the meaning of any existing policy.

03 · Process

How it maps to the real site.

During WordPress migration, the safest approach is to apply a shared policy wrapper or CSS scope to existing pages. That keeps the original page content intact while giving all policy and utility pages one visual system.

  1. Read the current WordPress page content.
  2. Confirm the page URL and menu location should stay the same.
  3. Apply shared utility-page classes and typography.
  4. Test desktop and mobile readability.
  5. Verify no policy text or SEO data was lost.

End with a clear route.

Most policy pages should end with a simple contact route, not a sales section. Link to the real Contact page, Track Order page or support email depending on the page type.
